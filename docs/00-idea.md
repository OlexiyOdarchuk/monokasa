# 00 · Ідея

## Один абзац

monokasa — це **friendly self-host** для продажу квитків на події. Один
бінарник дає тобі Telegram-бота, веб-сайт із мапою залу, адмін-панель і
сканер на вході. Платежі йдуть на твою банку моно напряму — без чужого
API в посередниках, без комісії платформи, без чужої БД. Розгортається
одним `docker compose up`.

## Кому це для

- Невеликі організатори: театри, інді-музика, лекції, stand-up, школи —
  події на 20–500 квитків.
- Технічно грамотні (вміють підняти Docker або заплатити комусь, хто
  вміє).
- Україна / monobank — це жорстко прив'язано до платіжної моделі банок.

## Не для кого

- SaaS-користувачі, які хочуть "зайти на сайт і налаштувати" без
  власного сервера.
- Великі майданчики з тисячами подій і вторинним ринком.
- Не-Україна (монобанка) або не-jar платіжки.

## Non-goals — свідомо НЕ робимо

- **Multi-tenant SaaS.** Один інстанс = один organizer. Платежі прямо
  на банку organizer'а. Чужі гроші не торкаємось. Деталі → [[70-decisions/why-self-host]].
- **Повернення коштів через API.** Рефанди — руками в моно.
- **Платіжний шлюз / еквайринг.** Тільки банки моно з `?a=…&t=…`. Деталі → [[70-decisions/why-monobank-jar]].
- **Складна авторизація сканера.** Shared-token достатньо.
- **Multi-show migrations.** Перший show seed-иться з ENV, далі — через
  адмін веб.

## Принципи, за якими побудовано

- **Прямий шлях гроші → квиток.** Жодного посередника. Покупець платить
  у моно, бот/сайт ловлять webhook і одразу шлють PDF.
- **Idempotent everything.** `Confirm`, міграції, webhook, reconcile —
  все ідемпотентне; повторне виконання не псує.
- **Одне знання — одне місце.** Кожен пакет має свій тип сутностей і
  свій інтерфейс залежностей. `cmd/app/main.go` склеює адаптери.
- **Self-host first.** Без Docker воно теж збирається (`make build`),
  без BASE_URL — теж працює (без WebApp кнопки), без SMTP — теж (тільки
  через Telegram).

## Ключові тези для розмови з користувачем

- "Самохост" = так, але friendly: Docker, first-run wizard через
  ADMIN_EMAIL+ADMIN_PASSWORD, адмін-веб для всього подальшого.
- "Платежі" = на твою банку моно, ми не дотягуємось до твоїх грошей.
- "Безпека" = HMAC-підписані QR, bcrypt-сесії, HttpOnly cookies,
  rate-limit на сканер.
- "Що буде, якщо webhook не дійде" = `/reconcile` від адмін-аккаунта
  бота. Деталі → [[40-flows/reconcile]].
